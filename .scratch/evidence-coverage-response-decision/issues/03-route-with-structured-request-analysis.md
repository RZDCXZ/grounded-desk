# 03 — 用请求分析器替代固定路由规则

**What to build:** 访客的自然语言消息由统一、版本化的请求分析器识别交流意图、事实诉求和信息完整性，使自然改写不再依赖持续扩充的表达集合、正则或主题白名单。

**Blocked by:** 02 — 迁移现有单项回答到分段契约.

**Status:** resolved

- [ ] 请求分析器使用严格结构化契约返回语言、交互类型、交流意图以及最多三项有顺序的事实诉求。
- [ ] 中文、英文和中英混合的问候、致谢、告别、身份、能力及范围外改写能够得到对应的受控交流性回应。
- [ ] 同时包含交流表达与事实诉求的消息必须进入知识处理路径，不能因问候、致谢或提示词注入绕过检索。
- [ ] 交流性回应继续只使用助手名称、服务范围、语气和语言组成的受控模板，不执行召回、重排、覆盖判定或回答生成。
- [ ] 请求分析调用计入 AI 预算和调用日志；预算耗尽返回额度阻断，而不是可靠拒答或技术故障。
- [ ] 分析超时、供应商错误或无效结构重试一次，仍失败时形成可重试技术故障且不创建待解决问题。
- [ ] 公开助手与管理员预览使用同一请求分析行为，确定性服务测试覆盖自然改写、混合消息、安全输入、预算和失败路径。
