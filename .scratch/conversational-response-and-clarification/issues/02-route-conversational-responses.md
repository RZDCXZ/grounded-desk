# 02 — 路由交流性回应并使用受控模板

**What to build:** 纯问候、致谢、告别、助手身份与能力询问以及明确范围外请求可以直接得到受控的交流性回应，同时任何业务问题仍进入知识检索。

**Blocked by:** 01 — 扩展会话结果与成本契约.

**Status:** ready-for-agent

- [ ] 建立服务端高置信输入路由，客户端不能指定或覆盖路由结果。
- [ ] 识别整条消息都是问候、致谢、告别、助手身份与能力询问或明确范围外请求的中英文场景。
- [ ] 只在整条消息属于交流性表达时走交流性回应；问候或致谢与业务问题混合时业务问题优先。
- [ ] 无法高置信分类的输入执行现有知识检索，不新增前置大模型分类调用。
- [ ] 为每个交流类别提供简体中文和英文受控模板，使用助手名称、服务范围和语气配置。
- [ ] 模板不得扩展业务事实、承诺、数字、链接或知识来源内容。
- [ ] 明确范围外请求只礼貌说明服务范围并引导访客返回，不自由完成笑话、代码或其他范围外任务。
- [ ] 交流性回应不调用 embedding、rerank 或 answer 供应商。
- [ ] 交流性回应显式完成为 `conversational_response`，引用为空。
- [ ] 后台预览和公开助手复用相同路由与模板行为。
- [ ] 添加公开会话边界测试，覆盖中英文、混合输入、范围外请求、疑则检索和无 AI 调用。
