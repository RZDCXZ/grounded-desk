# 03 — 对残缺问题最多澄清一次

**What to build:** 信息不足但已表达咨询意图的消息可以在证据不足时得到一次澄清提问，下一条消息结合近期上下文重新检索，仍无证据时可靠拒答。

**Blocked by:** 01 — 扩展会话结果与成本契约; 02 — 路由交流性回应并使用受控模板.

**Status:** ready-for-agent

- [ ] 在知识检索没有形成最终证据集后，区分明显残缺表达与已经完整的事实问题。
- [ ] 简短主题检索到充分证据时仍形成有据回答，不仅凭长度强制澄清。
- [ ] “退款”“价格方面”等残缺表达在无证据时形成 `clarification_request`。
- [ ] “多少钱？”“能退款吗？”等完整问题在无证据时继续形成可靠拒答。
- [ ] 澄清提问使用受控表达并引用当前主题，不加入未经知识支持的事实或业务选项。
- [ ] 下一条访客消息结合原主题和澄清提问重新执行检索。
- [ ] 同一对话不允许连续产生第二次澄清提问；再次无充分证据时可靠拒答并提供人工联系入口。
- [ ] 一个非澄清的已完成结果重置连续澄清状态。
- [ ] 澄清提问不附引用、不显示人工联系入口、不允许质量反馈且不创建待解决问题。
- [ ] 添加公开会话边界测试，覆盖有证据短主题、无证据残缺表达、完整短问题、澄清成功和澄清后拒答。

## Notes

- 完整范围见 [规格](../spec.md)。
- 首版不建立长期意图实体，也不跨会话保存澄清状态。
