# 06 — 验证交流路由并完成发布门槛

**What to build:** 开发者可以通过一个以公开助手会话为主接缝的验收矩阵，确认新交互更自然且没有放宽业务事实的证据边界。

**Blocked by:** 01 — 扩展会话结果与成本契约; 02 — 路由交流性回应并使用受控模板; 03 — 对残缺问题最多澄清一次; 04 — 更新访客端与预览端呈现; 05 — 在后台复盘新会话结果.

**Status:** ready-for-agent

- [ ] 使用公开助手会话作为唯一主测试接缝，覆盖流式响应、访客呈现、持久化结果、引用、反馈、待解决问题和 AI 调用日志。
- [ ] 数据库测试只覆盖必须由数据库强制的不变量，不为内部路由建立重复低层接缝。
- [ ] 覆盖中文和英文问候、致谢、告别、身份、能力和范围外请求。
- [ ] 覆盖问候加业务问题、致谢加业务问题、模糊输入和疑则检索。
- [ ] 覆盖有证据短主题、无证据残缺表达、完整短问题、澄清后成功和澄清后拒答。
- [ ] 验证交流性回应与澄清提问无引用、无人工入口、无反馈、无待解决问题。
- [ ] 验证交流性回应不产生 AI 调用并可在每日 AI 预算耗尽后返回。
- [ ] 验证所有消息仍受每分钟五条、每会话三十条和单一进行中回答限制。
- [ ] 验证后台列表筛选、详情标签和既有概览指标。
- [ ] 回归有据回答、可靠拒答、供应商故障、多轮上下文、引用、反馈、待解决问题和会话删除。
- [ ] 运行类型检查、静态检查、服务测试、数据库测试、端到端测试和生产构建。
- [ ] 确认没有降低重排证据阈值，也没有引入前置大模型意图分类调用。
